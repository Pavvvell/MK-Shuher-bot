# Шухер v0.2 — PostgreSQL + Telegram Mini App

**Гілка:** `feature/postgres-miniapp`. Не перемикайте бойовий реєстр до перевірки імпорту.

## Реалізовано

- PostgreSQL `ledger_records`: всі 6 вкладок Google Sheets, первинні ID та повні значення комірок без втрати коментарів, статусів, URL і посилань на документи. Індекси за проєктом і статусом.
- `ledger_events`: аудит створення, підтвердження оплат, приймання, зміни доручень.
- `ledger_attachments`: фото, документи (BYTEA, до 8 MiB на файл) та зовнішні HTTPS/HTTP посилання із прив'язкою до записів. Дані закриті серверною авторизацією через Telegram Mini App `initData`.
- Міні-застосунок `/app/`: пошук, картки, детальні поля, прикріплення файлів/посилань, створення заявки, зміна доручення, сторінка імпорту власника.
- Різні меню і API-права: `owner`, `buyer`, `storekeeper`. Ролі визначаються за поточними Telegram ID у Railway Variables.
- Міграція 6 аркушів: без запису в Google Sheets, з перевіркою кількості записів, захистом від повтору та звітом про конфлікти.
- Проміжний перемикач `DATA_BACKEND`: поточний Telegram-бот може залишитися на Google Sheets, доки PostgreSQL не перевірено.

## Railway Variables

**Усі наявні секрети залишити як є**: `DATABASE_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `PUBLIC_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`, `GOOGLE_SERVICE_ACCOUNT_JSON_B64`, `OWNER_IDS`, `BUYER_IDS`, `STOREKEEPER_IDS`.

Нові змінні:

```env
IMPORT_SOURCE_SPREADSHEET_ID=1ZSmctpTVh5NsCa4pW0acpo6CZGrddhOj9xjmTlsB03c
ENABLE_MINI_APP=true
DATA_BACKEND=sheets
```

Сервісний акаунт `shuher-sheets@mk-shuher-bot.iam.gserviceaccount.com` має **Reader** на бойову таблицю, що достатньо для імпорту. `SPREADSHEET_ID` поки залишити ID тестової таблиці — для старого режиму Telegram.

### Безпечний порядок переходу

1. Запустити новий деплой із гілки після успішного CI. Сервіс створить SQL-схеми автоматично.
2. У Telegram `@shuher_work_bot` відкрити меню **Шухер · база**. Авторизуватися під власником із `OWNER_IDS`.
3. У розділі **Міграція** натиснути **Перевірити джерело**. Контрольні кількості 16.10.2026: Заявки 28, Закупка 11, Склад 25, Доручення 5, Уточнення відомостей 1, Інвентаризація 1 (разом 71). Кількості можуть змінитися, якщо в реєстрі з'являться нові записи.
4. Натиснути **Імпортувати підтверджені дані**, перевірити JSON-звіт `inserted`, `existing`, `different_existing`. `different_existing` мають дорівнювати нулю для чистої бази. У розділах Mini App перевірити ключові записи `METK-1206-01`, `USM-SF0615-01`.
5. Відпрацювати тестову заявку через Mini App, перевірити, що вона лишилася тільки в PostgreSQL. Протестувати документи/посилання і права доступу на тестових записах.
6. Лише після звірки **перемкнути `DATA_BACKEND=postgres`** і застосувати конфігурацію через Railway. Відтоді Telegram-бот теж читає та пише в PostgreSQL; Google Sheets — архівна копія, не двостороння синхронізація.
7. Зробити резервне копіювання PostgreSQL перед початком реальної роботи, налаштувати регулярні бекапи й тест відновлення.

### Як швидко відкотити

Поки `DATA_BACKEND=sheets` — старий Telegram-бот продовжує використовувати тестову таблицю. Власник може вимкнути Mini App через `ENABLE_MINI_APP=false`; жоден імпорт не змінює Google-таблицю.

**Після переходу на PostgreSQL не можна просто повернути `DATA_BACKEND=sheets` як безпечний rollback**, якщо вже з'явилися нові записи. Спочатку треба експортувати і звірити PostgreSQL, інакше дані розійдуться.

## Які дані переносяться

Текстові коментарі, реквізити, статуси, ID, кількості, посилання та назви файлів із клітинок Google Sheets перенесуться як значення у JSONB.

**Фото й PDF, які колись були тільки в чатах ChatGPT, не переносяться автоматично.** Для їх перенесення потрібні самі файли. Нові вкладення можна додавати через Mini App; фізично їхні байти зберігаються в PostgreSQL до 8 MiB на файл. За зростання обсягів краще винести байти у S3-сумісне сховище, залишивши у PostgreSQL метадані і права.

## Безпека й обмеження

- Telegram `initData` перевіряється через HMAC-SHA256 та 24-годинне обмеження сесії; заборонений доступ без Telegram.
- Доступи/фільтрація доручень перевіряються backend-сервером, а не лише приховуванням вкладок.
- Не можна автоматично вважати рахунок оплаченим або поставку отриманою без відповідного підтвердження.
- Telegram-бот ще не вміє автоматично читати фото/PDF із чату, Mini App зараз підтримує прикріплення вже вибраних файлів до записів.
- Обмеження прикріплених файлів: 8 MiB, сховище PostgreSQL може швидко рости. Потрібні резервні копії та політика зберігання.
- Перший Mini App — легкий HTML/CSS/JS без додаткового фронтенд-сервера; надалі його можна замінити React + TypeScript, не змінюючи API.
- Поточний захист від повторних заявок: повторення однакової позиції тим самим Telegram-користувачем протягом 15 хвилин не створює другу заявку. Для масштабування потрібні ще транзакційні idempotency keys на кожній API-операції.
- Інтеграційні тести з реальними Railway/PostgreSQL/Telegram без ключів тут не виконувалися. CI перевіряє синтаксис та offline-перевірки авторизації.

```sh
node --check web/app.js
```
