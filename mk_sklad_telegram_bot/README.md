# МК Склад — Telegram + OpenAI API

**Початковий прототип v0.1. Не запущений у вашому Telegram, доки ви не створите бота та не налаштуєте доступи.**

Вільний текст українською, три ролі (власник, закупівельник, комірник), Google Sheets як **єдиний авторитетний реєстр для MVP**, PostgreSQL для підтверджень, журналу дій і захисту від повторних Telegram-подій.

## Уже реалізовано в коді

- Приватний Telegram-чат; `/id` показує Telegram ID, `/start`, `/help`, `/cancel`.
- Перевірка ролі за Telegram ID (інші користувачі не допускаються).
- Питання вільною мовою про актуальні дані реєстру: працівник бачить у відповідях лише аркуші, дозволені його ролі (власник — усі чотири, закупівельник — «Заявки», «Закупка», комірник — «Заявки», «Склад»).
- Нова заявка з тексту: попередній перегляд → підтвердження → запис у «Заявки».
- Підтвердження **вже проведеної** оплати лише власником: попередній перегляд → підтвердження → оновлення «Закупка».
- Фактичне приймання лише власником або комірником: звірка з закупівлею, одиниці та кількості → підтвердження → складська операція і залишок закупівлі однією Sheets batchUpdate.
- Повторні Telegram update_id і повторні ID заявок/приймань відсікаються; записи в Postgres про підтверджені дії.
- Telegram webhook із секретним заголовком; використання приватного чату, а не групи.

## Ще НЕ реалізовано

Автоматичний розбір фото/сканів/PDF, голосових; створення закупівель із рахунків; повідомлення іншим співробітникам; контроль дедлайнів; Mini App; повна міграція обліку в PostgreSQL; детальний технічний аудит виробничих замін.

**Не слід вважати цей прототип готовою бухгалтерською/ERP-системою.** Для виробничої експлуатації бажані інтеграційні тести на копії реєстру, резервні копії, журнал усіх ручних правок і формальна перевірка доступів.

## Запуск — потрібно налаштувати один раз

1. Створіть Telegram-бота через `@BotFather` командою `/newbot`. **Не надсилайте токен у чат або GitHub.**
2. Увійдіть до [OpenAI API Platform](https://platform.openai.com/) і налаштуйте окремий API billing. Підписка ChatGPT Pro/Business **не оплачує API-запити**.
3. Створіть окремий Google Cloud service account, увімкніть Google Sheets API, завантажте JSON credentials. Упакуйте JSON в base64 локально (`base64 < service-account.json | tr -d '\n'`). Email цього service account додайте як **Editor** до Google-таблиці.
4. **Увага до захищених аркушів:** у реєстрі вже встановлені protected ranges. Для запису ботом сервісний акаунт має бути доданий до редакторів відповідних захищених діапазонів «Заявки», «Закупка» і «Склад». Просто дати Editor на весь файл може бути недостатньо. Не прибирайте захист для людей заради бота.
5. Створіть **приватний** репозиторій GitHub та завантажте файли цього проєкту (без `.env`, JSON або токенів). У Railway створіть проєкт → Deploy from GitHub → цей репозиторій. Додайте Railway PostgreSQL у тому ж проєкті.
6. У Railway → ваш Python-сервіс → Variables задайте змінні з `.env.example`:
   - `TELEGRAM_BOT_TOKEN` — токен BotFather;
   - `TELEGRAM_WEBHOOK_SECRET` — випадковий секрет `openssl rand -hex 24`;
   - `PUBLIC_BASE_URL` — публічний HTTPS-домен сервісу Railway після Generate Domain (без `/` наприкінці);
   - `OPENAI_API_KEY` — **окремий** API-ключ;
   - `OPENAI_MODEL` — наприклад `gpt-4.1-mini`;
   - `DATABASE_URL` — reference `${{Postgres.DATABASE_URL}}` до Railway PostgreSQL (якщо БД називається `Postgres`);
   - `SPREADSHEET_ID` — ID чинного реєстру (вже є в прикладі);
   - `GOOGLE_SERVICE_ACCOUNT_JSON_B64` — вміст base64 JSON credentials;
   - `OWNER_IDS`, `BUYER_IDS`, `STOREKEEPER_IDS` — числові Telegram ID через кому, **не usernames**.
7. Після старту сервісу перевірте `https://YOUR-DOMAIN/health`. Напишіть боту `/id` (ця команда доступна до авторизації). Внесіть отримані числові ID у Variables → Redeploy.
8. Тестуйте **на копії Google-реєстру**, задавши її ID в `SPREADSHEET_ID`. Спробуйте /start, довільний запит стану, тестову заявку й `/cancel`. Тільки після перевірки дайте боту доступ до робочого реєстру.

### Рекомендований порядок розвитку

`v0.1` текстовий чат + ролі + підтверджувані записи → `v0.2` фото/PDF/ТТН/рахунки та коректне зіставлення документів із закупівлями → `v0.3` сповіщення й доручення → `v1` PostgreSQL як єдине джерело правди, Google Sheets лише звітна вітрина, міграція після перевірки.

### Безпека

Дозволяйте в боті лише особисті чати, не додавайте його до загальних груп. Ніколи не кладіть токени, service-account JSON та дані компанії у відкритий репозиторій. Витрати API налаштовуйте й контролюйте в OpenAI Platform. Бот працюватиме з документами вашої компанії; обговоріть, які типи даних дозволено надсилати в зовнішній ШІ API.

### Обмеження щодо тестування

Виконана перевірка синтаксису Python; інтеграційні виклики до Telegram, OpenAI, Google Sheets і Railway не виконані, бо немає ваших облікових даних. Прототип потребує розгортання та тестування до реальної експлуатації.
