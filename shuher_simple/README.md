# Шухер Lite — Telegram + GPT + Google Sheets

Мінімальний бот для МК Склад. Ніякого PostgreSQL, Cloud SQL, Mini App, оркестратора і міграції даних.

## Що працює

- **Власник:** `/users` (Telegram ID усіх, хто писав боту); `/create` (створити бізнес-вкладку); `/grant ID read|write Назва`; `/revoke ID Назва`.
- **Усі:** `/start` (реєстрація), `/id` (власний ID), `/tables` (тільки свої доступні), `/use Назва`, `/ask запит`, `/add дані`, `/status`, `/balance`, `/export` (CSV), `/cancel`.
- **Власник:** `/today` — підсумок позицій, що сьогодні надійшли до закупівлі (за київською датою).
- ШІ може коротко відповідати за даними доступної таблиці або готувати **новий рядок**. Створення рядка й зміна статусу вимагають «так». Статуси змінюються лише явною командою `/status`, без довільного редагування інших полів.
- **Створення таблиці тільки власником і тільки явною командою `/create`**. ШІ не створює таблиць, не видає доступів і не видаляє рядків; існуючий рядок можна змінити лише в дозволених статусних колонках командою `/status` та після підтвердження.
- Власник може переглядати всі Telegram ID; чужі ID недоступні звичайним користувачам. `/id` показує кожному лише його власний.
- Користувачі **не отримують прямого Google Drive доступу**. Права `read/write` перевіряє бот за Telegram ID. Якщо комусь вручну надати доступ до всього Sheets-файлу в Google, він зможе обійти Telegram-обмеження.

## Таблиці

**Один приватний Google Spreadsheet-файл** — у ньому кожна бізнес-таблиця є окремою вкладкою (sheet tab). Це дозволяє додавати їх без Google Drive OAuth та без окремих платних баз даних. **Для вимоги «лише власник бачить усі Telegram ID» цей файл має бути доступний тільки власнику та сервісному акаунту Шухера.** НІКОЛИ не ділитися ним із рядовими користувачами напряму.

Сховище технічних параметрів — приховані вкладки `_Shuher_Users`, `_Shuher_Access`, `_Shuher_Pending`, `_Shuher_Updates`. Вони створюються один раз під час запуску; це НЕ бізнес-таблиці. Власник не повинен видаляти або перейменовувати їх.

Нові бізнес-вкладки створюються **тільки** через:
```
/create Інструмент | Найменування, Кількість, Од. вим., Статус
/create Комуналка
```
Бот автоматично додає `ID`, `Дата` та `Автор`. У вже наявних вкладках додавання потребує першої колонки, назва якої починається з `ID` (`ID позиції`, `ID закупівлі` тощо); тільки перегляд працює без цього. Редагування довільних полів існуючих позицій не підтримується; доступна тільки зміна статусу через `/status`.


## Робочий процес МК Склад

- Заявки подають тільки працівники, яким власник дав `/grant ID write Заявки`. Додаткового погодження немає.
- Після `/use Заявки`, `/add 7 гайок М12, одиниця — шт.`, `так` бот додає заявку зі статусом `У закупці` **та пов'язану позицію закупівлі**. Поле `ID заявки` у «Закупка» дорівнює ID заявки, ID закупівлі формується як `ZK-` + ID заявки. Створення ідемпотентне: повторне підтвердження не створює ще одну позицію; при частковому збої можна повторити «так» протягом 30 хв.
- Уповноважений закупівельник обирає `/use Закупка` і може змінювати тільки дозволені статуси:
  - `/status ZK-SH-... | Статус замовлення | Замовлено`
  - `/status ZK-SH-... | Статус оплати | Оплачено`
- Для заявок і доручень, де лише одне статусне поле: `/status SH-... | Виконана` або `/status SH-... | Статус | Виконано`. Після зміни статусу обов'язкове підтвердження «так».
- `/today` — лише власнику; показує сьогоднішні рядки з «Закупка». Нічого не розсилається за розкладом.
- Комірник через `/use Склад` та `/add ...` записує надходження чи видачу **окремими рухами**. Вказані `ID заявки` та `ID закупівлі` звіряються з реальними рядками, а ID закупівлі може підставитись автоматично за заявкою.
- `/balance` або `/balance гайка` рахує залишки як **сума надходжень мінус сума видач** за однаковими найменуванням, характеристиками та одиницею виміру. Видача понад облікований залишок блокується. Місця зберігання не розбивають агрегований залишок на різні позиції.
- Доступ до статусів має тільки користувач із правом `write` до відповідної вкладки. Доступ до залишків — лише користувачеві, якому дозволено читати «Склад».

Це спрощений облік на Google Sheets, не транзакційна база. Не редагуйте ID або заголовки вручну. Висококонкурентні складські операції й часткові постачання з кількох джерел потребують розширення.

## Найкоротший деплой у Google Cloud Run (без Cloud SQL)

1. Проєкт GCP: `mk-shuher-bot`. У новому Gmail **створи окремий приватний Google Spreadsheet «Шухер — Робочі таблиці»** і надай `shuher-sheets@mk-shuher-bot.iam.gserviceaccount.com` роль **Editor**. Не надавай доступ іншим — бот сам контролює доступ за Telegram ID. Для безпечного пробного запуску можна тимчасово використовувати стару тестову копію `1cACUDeIyCLWFMpzJ5LP-udj5jqIkZ1s_etsX5dQyHP4`, але її доступи потрібно перевірити. Бойовий реєстр поки не зачіпати.
2. Запусти на Mac `gcloud auth login` під новим Gmail, `gcloud config set project mk-shuher-bot`.
3. `gcloud services enable run.googleapis.com cloudbuild.googleapis.com artifactregistry.googleapis.com sheets.googleapis.com`.
4. Відкрий `shuher_simple/`. Створи приватний локальний файл `deploy.env.yaml` (у .gitignore, .gcloudignore та .dockerignore). Не надсилай його в чат і не коміть:
```yaml
TELEGRAM_BOT_TOKEN: "ЧИННИЙ_ТОКЕН_БОТА"
TELEGRAM_WEBHOOK_SECRET: "ЧИННИЙ_WEBHOOK_SECRET"
OPENAI_API_KEY: "ЧИННИЙ_OPENAI_КЛЮЧ"
OPENAI_MODEL: "gpt-4.1-mini"
SPREADSHEET_ID: "ID_НОВОГО_ПРИВАТНОГО_SPREADSHEET"
OWNER_IDS: "ТВІЙ_ЧИСЛОВИЙ_TELEGRAM_ID"
REGISTER_TELEGRAM_WEBHOOK: "false"
```
5. Із каталогу `shuher_simple/` виконай `sh deploy.sh`. Скрипт створює Cloud Run без Cloud SQL, але **ще не перемикає Telegram**.
6. Переконайся, що `/health` повертає `{"status":"ok","backend":"google-sheets"}`.
7. Коли все готово — `sh activate.sh`, підтвердь словом `ACTIVATE`. Ця дія перемкне Telegram webhook на Google Cloud Run.
8. У Telegram: `/start`, `/users`, `/create ТЕСТ-ШУХЕР | Найменування, Кількість, Одиниця`, `/use ТЕСТ-ШУХЕР`, `/add 7 гайок М12`, `так`.

**Для більш детального ручного деплою** команди залишено у `deploy.sh` та `activate.sh`; вони не містять ключів.

Цей бот читає дані вже наявних вкладок вибраної таблиці, нічого не мігрує. Перший запуск — тільки на тестовому Spreadsheet; після перевірки виберемо остаточний робочий файл.

## Безпека та компроміси

- Чужі Telegram ID можна отримати тільки командою `/users` з `OWNER_IDS`; `/grant` і `/create` додатково перевіряють власника.
- Webhook приймає лише запити з правильним `X-Telegram-Bot-Api-Secret-Token`.
- CSV `/export` надсилається тільки користувачу з доступом через приватний Telegram-чат.
- Поточний Telegram webhook містить лише одного активного отримувача; перед зміною хостингу не запускати два сервіси зі встановленням webhook одночасно.
- Повідомлення та текстові дані читає OpenAI API при AI-запиті. Не використовувати для секретів, не призначених стороннім процесорам.
- Поточна версія не обробляє PDF/фото/аудіо з Telegram і не редагує довільні поля існуючих рядків. Дозволені лише статуси.
- Більші таблиці й дуже часті одночасні записи потребуватимуть окремих гарантій ідемпотентності. Для декількох користувачів `max-instances=1`, `concurrency=1` та перевірки ID достатні для початкового тесту, але це не транзакційна БД.
- Прямий доступ до Spreadsheet-файлу у Google НЕ обмежується ботом по вкладках. Якщо потрібні прямі редактори Gmail із різними дозволами, доведеться створювати окремі Spreadsheet-файли або залишити доступ тільки через Telegram.
- Cloud Run має безплатний рівень, але API OpenAI, вихідний трафік і збірки можуть оплачуватись окремо.
